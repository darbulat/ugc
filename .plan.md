# План: Второй канал связи с креаторами через бот в мессенджере Max

## Текущая архитектура

Кодовая база уже подготовлена к мультимессенджеру:

1. **`MessengerType` enum** (`domain/enums.py`) — уже содержит `MAX = "max"`
2. **Messenger-neutral DTOs** (`application/messenger/dto.py`) — `IncomingMessage`, `IncomingCallback`, `Keyboard`, `Button` — полностью абстрактны от Telegram
3. **Порт `MessengerClient`** (`application/messenger/ports.py`) — Protocol с методами `send_text`, `send_photo`, `edit_text`, `edit_reply_markup`, `answer_callback`, `send_invoice`
4. **Порт `MessengerEventAdapter`** (`application/messenger/ports.py`) — Protocol для конвертации нативных событий в DTO
5. **`MessageContext` / `CallbackContext`** (`application/messenger/context.py`) — обёртки с aiogram-like API, работающие поверх `MessengerClient`
6. **Сервисный слой** — все сервисы (20+ штук) работают через абстрактные порты, не зависят от Telegram

Telegram реализация:
- `infrastructure/messenger/telegram/client.py` → `TelegramMessengerClient(MessengerClient)`
- `infrastructure/messenger/telegram/adapter.py` → `TelegramEventAdapter(MessengerEventAdapter)`
- `telegram_webhook_app.py` → FastAPI endpoint `/webhook/telegram`
- `app.py` → `build_dispatcher()` строит aiogram Dispatcher с routers + middleware

## Библиотека для Max

**`maxapi`** (PyPI, v0.9.17, март 2026) — основная библиотека:
- Async Python, ≥3.10
- `Bot`, `Dispatcher`, `Router` — архитектура аналогична aiogram
- Поддержка webhook (FastAPI + uvicorn) и polling
- Middleware: `BaseMiddleware` с `__call__(self, handler, event_object, data)`
- Фильтры: `Command('start')`, `F.message.body.text` (MagicFilter)
- Events: `MessageCreated`, `MessageEdited`, `MessageCallback`, `BotStarted`
- Inline keyboards, callback buttons, attachments
- FSM: `MemoryContext` для управления состоянием

## План реализации

### Шаг 1: Инфраструктура Max (новые файлы)

```
src/ugc_bot/infrastructure/messenger/max/
├── __init__.py
├── client.py          # MaxMessengerClient(MessengerClient)
├── adapter.py         # MaxEventAdapter(MessengerEventAdapter)
└── state.py           # Маппинг FSM состояний (если нужен)
```

**`client.py`** — реализация `MessengerClient` через `maxapi.Bot`:
- `send_text()` → `bot.send_message(chat_id, text, attachments=[inline_keyboard])`
- `send_photo()` → через Max API attachments
- `edit_text()` → `bot.edit_message(message_id, text)`
- `edit_reply_markup()` → `bot.edit_message(message_id, attachments=[keyboard])`
- `answer_callback()` → `bot.answer_callback(callback_id, text)`
- `send_invoice()` → Max пока может не поддерживать платежи — заглушка с NotImplementedError или fallback

**`adapter.py`** — конвертация `maxapi.types.MessageCreated` → `IncomingMessage`, `MessageCallback` → `IncomingCallback`:
- `from_message(event: MessageCreated)` → `IncomingMessage(chat_id, user=IncomingUser(external_id, MessengerType.MAX, username), text, ...)`
- `from_callback(event: MessageCallback)` → `IncomingCallback(...)`

### Шаг 2: Конфигурация

В `config.py` добавить секцию:
```python
class MaxBotConfig(BaseSettings):
    max_bot_token: str = ""
    max_webhook_base_url: str = ""
    max_webhook_secret: str = ""
```

### Шаг 3: Webhook endpoint для Max

**`max_webhook_app.py`** — аналог `telegram_webhook_app.py`:
- FastAPI app с lifespan:
  - Создаёт `maxapi.Bot(token=...)`
  - Создаёт `MaxMessengerClient(bot)` и `MaxEventAdapter()`
  - Регистрирует webhook `/webhook/max`
- Два варианта:
  - **Вариант A**: Отдельный процесс/контейнер на отдельном порту (аналогично instagram_webhook_app)
  - **Вариант B**: Добавить endpoint в существующий `telegram_webhook_app.py` (проще, но связывает)

  **Рекомендация: Вариант A** — отдельный entry point `max_webhook_app.py` на порту 8003

### Шаг 4: Маршрутизация событий Max → существующие хендлеры

Ключевая задача — переиспользовать логику из `bot/handlers/` без дублирования.

**Подход**: Создать прослойку, которая:
1. Принимает maxapi events через webhook
2. Конвертирует через `MaxEventAdapter` в DTO
3. Оборачивает в `MessageContext`/`CallbackContext`
4. Вызывает общую бизнес-логику (сервисный слой)

**Проблема**: Сейчас handlers в `bot/handlers/` напрямую используют aiogram Router/Dispatcher и aiogram types. Они не вызывают сервисы напрямую — они сами IS the handler layer.

**Решение в 2 этапа**:
1. **Быстрый MVP**: Создать отдельный набор Max-хендлеров в `bot/handlers_max/` который регистрируется на maxapi Dispatcher, использует те же сервисы из контейнера, но через maxapi events → DTO → service calls
2. **Долгосрочно**: Вынести общую логику хендлеров в messenger-neutral слой, вызываемый из обоих наборов хендлеров

### Шаг 5: FSM (состояния)

maxapi поддерживает `MemoryContext` для FSM. Для консистентности при использовании Redis FSM (чтобы пользователь мог продолжить с любого мессенджера):
- Реализовать общий FSM storage через Redis с ключами `{messenger_type}:{user_id}`
- Или использовать встроенный maxapi FSM отдельно от aiogram FSM

### Шаг 6: Docker/Deploy

В `docker-compose.yml`:
```yaml
max_bot:
  build: .
  command: uvicorn ugc_bot.max_webhook_app:app --host 0.0.0.0 --port 8003
  environment:
    - MAX_BOT_TOKEN=${MAX_BOT_TOKEN}
  ports:
    - "8003:8003"
```

В nginx — проксирование `/webhook/max` → `max_bot:8003`

### Шаг 7: Миграция БД

Не нужна — `MessengerType.MAX` уже есть в enum. Пользователи с Max будут сохраняться с `messenger_type=max`.

## Ограничения и риски

1. **Платежи**: Max API может не поддерживать invoice/payments — нужна альтернатива (внешние ссылки на оплату)
2. **Mini App**: Telegram Mini App (`miniapp/`) не будет работать в Max — нужен отдельный web-интерфейс или пропустить
3. **Медиа**: Формат file_id различается между мессенджерами — нельзя переиспользовать telegram file_id в Max
4. **Username**: В Max username может быть другим — связка пользователей через внутренний UUID, не через внешний ID
5. **FSM State**: Если пользователь зарегистрирован в обоих мессенджерах, нужна логика объединения аккаунтов

## Что реализовать первым (MVP)

1. `infrastructure/messenger/max/client.py` — отправка сообщений
2. `infrastructure/messenger/max/adapter.py` — конвертация событий
3. `max_webhook_app.py` — entry point
4. `config.py` — Max bot token
5. Базовые handlers: `/start`, регистрация блогера, просмотр офферов, ответ на оффер
