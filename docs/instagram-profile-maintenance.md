# Актуальность Instagram-профилей

Механика использует результаты **существующего** планового Meta-сборщика.
Новый обход базы, Discovery-сбор, платные провайдеры и второй webhook не нужны.
До включения флага новые наблюдения и уведомления не создаются.

## Поведение

- Успешный ответ с прежним Meta ID и новым ником обновляет основную ссылку
  и Instagram в списке соцсетей. Предыдущий ник остаётся в истории.
- Ответ без числа подписчиков сохраняет ранее известное число и дату метрики.
- При подтверждении другого аккаунта прежняя статистика сохраняется в БД,
  но не используется в новых подборках. Нужны данные после смены аккаунта,
  относящиеся к его текущему нику; запоздалый ответ про прежний ник не подходит.
  Перенос даты попытки после ошибки сбора не считается новой статистикой.
- 100/33 и «user not found» не означают доказанное удаление аккаунта. Два
  неуспешных наблюдения с интервалом минимум 6 часов переводят его на проверку.
  Существующее подтверждение, заказы, рейтинги и финансовые записи сохраняются.
  Новые подборки и передача контакта учитывают статус проверки.
- Ошибки токена, таймауты и лимиты не ухудшают статус блогера. Если весь пакет
  проверок завершился без единого успешного профиля, статусы не ухудшаются.
- На один эпизод создаётся один запрос владельцу. Кнопка «Обновить Instagram»
  открывает редактирование существующего профиля в Telegram или MAX. После
  отправки корректной ссылки требуется обычное подтверждение кодом, даже если
  ссылка осталась прежней. Нажатие кнопки само подтверждение не снимает.
- Восстановление доступа или свежая верификация отменяет ожидающий запрос.
  Новый ID принимается только существующим процессом подтверждения владения.
- При изменении подтверждённой ссылки заказчик действующего заказа получает
  актуальную ссылку. Получатель и связь с заказом проверяются перед отправкой.
  Исторические снимки платной подборки не переписываются. Смена ника при прежнем
  ID не блокирует ещё не отправленный контакт; используется текущая ссылка.

## Время и доставка

Все **новые уведомления этой механики** отправляются с **08:00 включительно
до 21:00 исключительно по Europe/Moscow**. Ночью они остаются в БД. Время
проверяется при получении задания и непосредственно перед запросом провайдеру.
Плановые проверки Meta могут работать ночью; уведомления ждут утра.
Напоминания об истечении токенов эта механика не меняет.

Очередь обрабатывается раз в минуту, до 20 сообщений за проход. Два процесса
не забирают одно задание одновременно. Подтверждённый 429 откладывается с
повторной проверкой времени. Неопределённый результат сетевого запроса и
истёкшая аренда отправителя получают `unknown`, без автоматического повтора.
`sent` означает принятие сообщения провайдером, а не прочтение пользователем.

## Идентификаторы

`instagram_profile_health` хранит тип ID и контекст приложения/бизнес-аккаунта.
Исторические ID обозначаются `legacy_meta_id`; свежий sender ID из прошедшей
проверки кода — `instagram_scoped_id`. Публичный ID из ScrapeCreators остаётся
в исходных данных статистики и не подставляется в Meta ID для верификации.
`instagram_profile_observations` — неизменяемая история; токенов и сырых
ответов Meta в ней нет. Ошибка 100/33 не позволяет определить новый ник.

## Включение и откат

1. Выполнить ревью текущего PR, дождаться CI и сделать обычный резервный снимок.
2. Применить аддитивную миграцию `0145_instagram_profiles` один раз до новых
   приложений. Старые образы совместимы с дополнительными таблицами.
3. Сначала обновить обработчики Telegram/MAX и единственный Instagram webhook
   с флагом выключенным. Использовать действующие токены. Webhook не дублировать.
4. Обновить существующие `combined_scheduler`, `instagram_stats_scheduler`
   и используемые сборщики статистики с новым кодом репозитория.
   Сохранить ближайшее плановое время каждого сборщика: обычный перезапуск
   запускает сбор сразу, поэтому применять предусмотренный отложенный старт.
5. На затронутых сервисах включить `INSTAGRAM_PROFILE_MAINTENANCE_ENABLED=true`
   и одинаковый `INSTAGRAM_IDENTITY_CONTEXT=instagram_login:<app-id>:<umc-id>`.
   Для текущей связки: `instagram_login:1587344562417991:17841436959803981`.
   Сверить эти несекретные ID с действующим приложением перед выпуском.
6. Дождаться штатного цикла. Проверить наблюдения, отсутствие массовых ошибок,
   работу подписанного webhook и доставки в дневное окно. Не запускать обход
   вручную и не рассылать тестовые сообщения реальным блогерам.

Для остановки новых запросов сначала выключить/откатить отправителя очереди,
затем производителей. Оставить таблицы и историю. Не повторять задания
`unknown` без ручной проверки результата. Откат миграции после появления
данных намеренно запрещён. Перед заменой любого контейнера заново сверить
действующие образы, Compose-метки и окружение согласно AGENTS.md.

Ограничение: актуальность зависит от действующего интервала и размера пакета
Meta, а недоступный ID не раскрывает новый ник. Для такого случая нужен ответ
владельца и свежая проверка. Накопленные ошибки до включения не импортируются
как два новых наблюдения и не вызывают немедленную рассылку.
