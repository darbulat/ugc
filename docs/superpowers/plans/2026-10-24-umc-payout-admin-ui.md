# UMC payout admin UI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for bounded inline execution after root releases source ownership. Steps use checkbox tracking. This document is a plan, not an implementation or an acceptance record.

**Goal:** Give a currently active Telegram/MAX payout administrator the remaining publication, bounded queue/detail/history, reasoned decision, audited reveal and actual-bank-observation screens, preserving the distinction between preparing manual execution, retaining a bank fact and applying a payout.

**Architecture:** Add a separate memory-only admin controller and stylesheet beside the frozen owner controller. Enter through current server capabilities, obtain a fresh opaque `createRequestContext()` from the existing signed bridge, consume the actual 9ga/9gb DTOs and use the existing command endpoints. Keep protected reads, selected-request authority and the active form in independently owned regions so background responses cannot replace forms or change the subject of a decision.

**Tech Stack:** Existing plain JavaScript/CSS/HTML, supplied UMC archive tokens/local fonts/brand assets, `UMCShell`, synthetic Playwright journeys against both actual templates, Node syntax checks and in-process ASGI static-byte checks without lifespan.

**Spec:** `docs/superpowers/briefs/umc-full-sprint/task-9g-payout-ui.md`, including root's accepted stages and 9ga clarifications; actual `src/ugc_bot/miniapp/payout_api.py`, `payout_view_api.py`, `payout_wire.py`, `application/services/payout_view_service.py`, `application/services/payout_service.py`, `application/payout_contracts.py`; `docs/superpowers/plans/2026-10-24-umc-payout-owner-ui.md`; supplied archive provenance `src/ugc_bot/miniapp/design-system/PROVENANCE.md`.

## Global constraints

- This is bounded **9gc-2 admin UI**. 9gc-1 owner review fixes must land and be reviewed before its controller/hooks are extended. The two reported owner findings are background reads clearing an active form and a late detail response replacing a later selection; do not edit around or refactor that worker's pending fixes.
- No financial backend, DTO, endpoint, database, migration, flag, provider, legal-policy, identity-policy or calculation change is assumed or authorized by this plan. No bank transfer, production publication, notification, activation, credential inspection, commit, push or deployment belongs to this task.
- Use the existing supplied UMC mint section, rounded cards, type scale, `--bg`, `--card`, `--ink`, `--muted`, `--line`, `--line-strong`, semantic notice/danger tokens and local assets. No alternate visual system, imagery, remote font or dependency. Preserve the archive's existing Kazakh font fallback.
- Complete RU/EN/KK/BE/UZ chrome, actions, errors and state copy with RU fallback. Full terms and field labels/help/values remain the actual publication's source data; no invented legal content, translation, tax status, minimum, fee, bank/provider fact or link resolver.
- All admin forms, document drafts, protected rows, reveal plaintext, recipient evidence, reasons/references/hashes and operation keys live only in private memory/required form controls. Never use local/session/IndexedDB storage, URL/hash/query, console, telemetry, data attributes, clipboard convenience or export for them. Clear all admin state on close/back, departure, account/platform change, pagehide and observed admin-role loss; also clear captured secret form values/payload objects on submit completion and abandonment.
- Authentication remains private to the bound bridge. Never pass body actor/recipient/admin selectors or copied initData. `_me`, role choice, staff-manager association and a cached `admin` flag are not protected-read or mutation authority. Every protected response/command still reauthorizes server-side.
- Capabilities and `allowed_actions` are current snapshot hints. Pause disables ordinary mutations as advertised but must not hide a server-permitted actual observation for a retained execution. Reveal and readable history remain independently usable when allowed. Do not make a single global `writes_paused` switch disable all admin actions.
- Monetary wire values are canonical decimal strings. Request money uses the existing exact RUB formatter. Observed signed money must retain the actual `[-9223372036854775807, 9223372036854775807]` range and optional null; never use Number/parseFloat/floating arithmetic/Number-based Intl for money. Versions may use validated safe integer numbers; no fabricated version `1`, fence or execution scope.
- Every async response is tied to the bound context, controller lifetime, read request, request selection and, where applicable, captured form/operation. A response or finally for A cannot clear B's form, replace B's detail, restore closed secrets or enable an inactive native action.
- An unknown admin send triggers protected reads before any further explicit decision. Never auto-replay, silently change expected version/key/payload, infer absence from a page or offer a replacement payment. Reload discards the form/key and does not reconstruct a command. The own-only `/payouts/operations/status` cannot recover administrative commands.
- All supplied text is rendered with element creation and `textContent`; document paragraphs use preserved whitespace. Opaque references are displayed as references, not executed HTML/Markdown or invented clickable documents.

## Review focus

1. A queue/history/context read or A's finally finishes while a reason/evidence/publication/reveal form B is being edited: B's DOM, values, ownership and final action must remain unchanged. Task 1/2 tests `test_admin_background_reads_preserve_active_form` and `test_admin_old_completion_cannot_clear_new_form` pin this.
2. Detail A, its history continuation or its reveal completes after B is selected, after departure, or after account/role loss: render and cleanup must remain scoped to the captured request/selection/context. Task 1/2/4 tests pin each response class, not just screen generation.
3. A future latest publication differs from the currently effective publication, or the latest publication lacks a readable companion: show both honestly, capture the actual latest version for publishing and allow a disabled publication without invented legal text. Task 3 pins this.
4. A real retained execution survives pause/key loss/unavailable current authority, or lacks proven version: preserve actual-result intake using real scope/provenance and a separately labelled operator-recorded version when needed; never promote retained facts to current authority. Task 5 pins this.
5. A command reply is lost, stale or reports a blocked/unapplied fact while current state is paid/rejected or later changes: show original reply, protected observation/application and current status separately, then require an explicit decision. Task 4/5 pin this; a 200 alone is never payment proof.

## Actual contracts to implement against

All paths below are signed **POST** bridge paths relative to `/miniapp/api`. Do not use old unbounded `/admin/queue`, `/admin/requirements`, `/admin/{id}/history` for new navigation. Read pages send `{limit: 20, cursor: null | opaqueToken}`; body/query actor selectors remain forbidden. Keep each continuation in memory scoped to its actor/context, route, request and history kind. Pages return `entries`, `has_more`, `next_cursor`, `as_of`; pages are independently fresh snapshots, not one cross-request transaction.

- `/payouts/read/context`: `actor_id`, `as_of`, `account_status`, `admin`, `writes_paused`, `requirements` (currently effective), admin-only `latest_publication`, and capability booleans `read_admin_queue`, `read_admin_requirements`, `publish_requirements` alongside owner fields. A successful current context and its exact capability gate entry; the admin controller obtains this itself through a fresh bound context.
- `/payouts/read/admin/queue`: bounded oldest request membership including nonterminal/blocked rows. Entries contain safe request fields plus admin detail extensions. Render queue rows with request ID, exact amount/currency, mask, state, requested/deadline/as-of, server `overdue` and safe blockers; do not invent a total or a local overdue eligibility calculation.
- `/payouts/read/{request_id}/detail`: safe fields `request_id`, `amount_minor`, `currency`, `requisites_id`, `requirements_id`, `requested_at`, `deadline_at`, `overdue`, `masked_label`, `state`, nullable `version`, nullable `execution_id`, `block_reason`, `as_of`; admin additions `allowed_actions`, `action_blockers`, `current_execution`, `observation`.
- Detail `current_execution` and `observation.retained_intents.entries` use `execution_id`, `fence`, `bank_account`, `prepared_at`, `amount_minor`, `currency`, `expected_version`, `version_provenance`. `observation` also has `can_record`; retained intents have `has_more`/`next_cursor` for the actual protected `history/intents` route. Provenance is `current_authority`, `retained_event` or `retained_version_required`.
- `/payouts/read/admin/requirements`: protected bounded publications with `requirements_id`, `version`, `effective_from`, `terms_reference`, `required_fields`, `enabled`, `readable`, `document`, `field_definitions`, `actor_id`, `recorded_at`, `legal_reference`, `evidence_reference`, `reason`. Document keys are `document_id`, `content_text`, `source_locale`, `sha256`, `publisher_id`, `recorded_at`; definitions are `key`, `labels`, `help`, `allowed_values`.
- `/payouts/read/admin/{request_id}/history/{kind}` with kind exactly `events|intents|outcomes|settlements`: independent page for each selected kind. Events expose event/request/version/action/state/actor/reason/time and optional validated `resulting_state`/`evidence_reference`. Intent history exposes execution/request/actor/fence/amount/currency/bank/prepared time plus **`version`** and `version_provenance` (not detail's `expected_version`). Outcomes expose outcome/request/execution/actor/status, optional amount/currency/settled time, bank account/reference, evidence reference/hash, recorded time, `applied`, `review_reason`. Settlements expose execution/request/outcome/amount/currency/bank account/reference/settled time. Never expect ciphertext/fingerprint/key ID, recipient plaintext, operation keys or reveal receipts in these pages.
- `/payouts/admin/requirements/publish`: `operation_key`, `expected_version` (integer >=0), aware `effective_from`, nonblank `legal_reference`, `terms_reference`, `evidence_reference`, `reason` (each <=4000), exact `required_fields`, boolean `enabled`, optional `document`, optional `field_definitions`. A document is either `{content_text, source_locale}` or `{document_id}` for an actual existing immutable document, never both. The server calculates SHA-256. The returned publication is an original receipt; refetch effective/latest/history separately.
- `/payouts/admin/command`: `operation_key`, selected `request_id`, captured `expected_version` (integer >=1), `action: review|reject|start|escalate`, nonblank `reason` <=4000 and `evidence_reference` <=4000 (required/nonblank for review/start). Requested review/reject/start may return blocked. Start returns the normal request view plus `fence`; reread protected detail/history for committed execution. Escalation does not pay or release funds.
- `/payouts/admin/{request_id}/requisites`: `operation_key`, nonblank `reason` <=4000. Returns the frozen details map itself after current-admin authorization and audit. No separate reveal-history/receipt endpoint exists; protected event pages do not prove that reveal audit was or was not written.
- `/payouts/admin/result`: `operation_key`, selected request/execution UUIDs, actual fence UUID, `expected_version` >=1, `status: paid|failed|unknown`, nonblank reason/evidence reference <=4000, lowercase 64-hex evidence hash, optional bank account/reference strings <=256, optional canonical signed `amount_minor`, optional currency <=20, optional aware `settled_at`, `recipient_details` object. The ordinary response is a request view and need not contain top-level `applied`/outcome ID; inconsistent-state replies can contain them. Always read protected outcomes for actual `applied`/`review_reason` and read current detail separately.
