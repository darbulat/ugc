## Shared contracts decided by this plan

### Versions and exact intents

`campaign_version` is the optimistic lifecycle version. `revision_version` always refers to the immutable physical `campaign_draft_revisions.version`; `revision_digest` retains its accepted meaning/hash unchanged. Bootstrap a legacy draft-only campaign's lifecycle version from its highest revision version when first touched. Every accepted mutation advances `campaign_version` once. New draft saves use the next lifecycle version as the new revision's physical version, so gaps in revision numbers are valid and old rows/hashes are untouched. Own/detail responses keep `version` as the current command version and add `revision_version`; the saved original receipt remains original and includes `is_current`/current status separately on replay.

Allowed lifecycle transitions here are draft → submitted → approved_waiting/rejected; submitted/approved_waiting → cancelled/expired; rejected/expired/cancelled unstarted work may save a new immutable revision → draft and submit again. Saving while submitted/approved_waiting conflicts. Every resubmission consumes a new submission unit. No attempt exists in this slice; a later worker must make content changes after any attempt create a new campaign. Add that guard when the actual attempt table exists rather than inferring it from a fake placeholder.

Use frozen typed commands, strict `parse(actor_id, payload)` allowlists and existing `digest/canonical`. No recipient/owner/native/role/contact override is accepted:

- `SubmitCampaign(actor_id: UUID, operation_key: str, campaign_id: UUID, expected_version: int, revision_digest: str, policy_version: int, terms_hash: str)`.
- `ReviewCampaign(actor_id: UUID, operation_key: str, campaign_id: UUID, submission_id: UUID, expected_version: int, revision_digest: str, review_context: str, decision: Literal['approve','reject'], reason: str)`.
- `CancelCampaign(actor_id: UUID, operation_key: str, campaign_id: UUID, expected_version: int, reason: str)`.
- `SettleCampaignExpiry(actor_id: UUID, operation_key: str, expected_policy_version: int, reason: str)`; no client time, target list or batch override.

UUIDs are nonzero; versions are actual strict positive ints (new-draft expected zero remains existing behavior); digests are lowercase 64-hex; keys retain the existing 256-character ceiling; reason is trimmed, nonblank and at most the foundation's existing 1000-character provenance ceiling. Command hashes cover action and every intent field above except actor (receipt is actor-scoped). Typed native proof is an explicit method keyword, never a command/content/context hash field or stored initData/token. Same actor/key plus different intent conflicts across **all new moderation actions**; legacy draft receipts keep their existing table/encoding and action.

### Transaction repository interface and ordering

`CampaignModerationRepository` defines these keyword-only caller-session methods:

- `preflight(actor_id: UUID, campaign_id: UUID | None, submission_id: UUID | None, *, purpose: Literal['draft','submit','decide','cancel','settle'], session: object) -> CampaignPreflight` — preliminary ownership/source identifiers, the complete prospective User set and provisional diagnostics only. Every capacity, source-set, scoped-absence or eligibility finding remains internal/provisional; this method emits no campaign-derived refusal or counters and does not resolve replay.
- `prepare(preflight: CampaignPreflight, *, principal: P, session: object) -> CampaignWriteContext` — verifies one active root READ COMMITTED caller transaction, complete sorted User → history → campaign barriers, refreshed held actor/native facts and bound session/root token. It records a refreshed prospective-set change for later new-admission validation instead of throwing a private scope/capacity refusal before receipt resolution. After current native/action-specific actor validation, the service resolves its actor-scoped receipt before returning any new-admission refusal. Missing transaction capability is unavailable before any write; nested/foreign/stale prepared contexts are refused.
- `begin_read(actor_id: UUID, *, principal: P, session: object) -> CampaignReadContext` — RR READ ONLY before first SELECT, checks fresh actor UUID/native columns in that same snapshot before private facts, no writer/advisory locks.
- `state(campaign_id: UUID, *, context: CampaignReadContext | CampaignWriteContext, session: object) -> CampaignState | None`; `submission(submission_id: UUID, *, context, session) -> CampaignSubmissionFacts | None`; `sources(submission_id: UUID, *, context, session) -> tuple[CampaignSourceFacts, ...]`.
- `candidates(owner_id: UUID, *, context, session) -> tuple[CampaignCandidateFacts, ...]`; `sender_snapshot(owner_id: UUID, *, context: CampaignWriteContext, session: object) -> CampaignSenderSnapshot`.
- `command(actor_id: UUID, operation_key: str, *, context, session) -> CampaignCommandReceipt | None`; `append_submission(write: CampaignSubmissionWrite, *, context: CampaignWriteContext, session: object) -> None`; `append_decision(write: CampaignDecisionWrite, *, context: CampaignWriteContext, session: object) -> None`; `append_terminal(write: CampaignTerminalWrite, *, context: CampaignWriteContext, session: object) -> None`; `save_receipt(receipt: CampaignCommandReceipt, *, context: CampaignWriteContext, session: object) -> None`.
- `owned_page(owner_id: UUID, page: int, *, context: CampaignReadContext, session: object) -> tuple[CampaignOwnedDetail, ...]`; `review_page(page: int, *, context: CampaignReadContext, session: object) -> tuple[CampaignReviewSummary, ...]`. Reuse existing 25-row/26th-row pagination; that is a technical read bound, not a quota.

`CampaignCapacityRepository` defines `facts(owner_id: UUID, recipients: tuple[CampaignRecipientScope, ...], *, at: datetime, context: CampaignWriteContext | CampaignReadContext, session: object) -> CampaignCapacityFacts`; `due(*, at: datetime, limit: int, context: CampaignWriteContext, session: object) -> CampaignExpiryBatch`; and `append(write: CampaignCapacityWrite, *, context: CampaignWriteContext, session: object) -> None`. Facts include immutable usage timestamps from all publications plus every unreleased/unconsumed reservation and active occupation; never a policy-keyed resettable total. The SQL adapter validates the prepared context's same session/root transaction before writes.

Write order is mandatory:

1. Preflight only the source/ownership identifiers and minimum server-owned candidate facts needed to discover owner, actor, frozen source users and all their current inviter/context users; approval includes the original reviewer where relevant. These untrusted preliminary facts cannot authorize a role, replay, private response, refusal or mutation. Every capacity finding, including over-cap/empty/backlog, is **provisional**. For submit, shared server-owned evaluation discovers the entire prospective candidate/User scope, including an over-cap set; do not cap that lock set at `recipients_per_campaign` or a sentinel prefix. A source scan may stream/page, but cannot silently truncate the final scope or ignore a later duplicate destination. Do not preload task/envelope/receipt result bytes for return before native validation.
2. Acquire every relevant existing User `FOR SHARE` in UUID order for that complete preflight scope, including over-cap candidates. This is the normal **complete** campaign barrier, never an actor-only early lock or a separate authentication lane. Keep fresh selected UUID/TG/MAX facts for validation after the history/campaign waits. Native remapping/status/contact writers must conflict with these shares; do not alter their frozen implementation.
3. Acquire `HISTORY_SNAPSHOT_LOCK_SQL` (shared `(2119754201,170434819)`), then existing campaign exclusive transaction advisory lock `(2119754201,170434820)`. Refresh held actor/native facts, require the current typed mapping and current action-specific actor authority, then read the actor-scoped operation receipt. Native mismatch returns only the known native denial (HTTP 403, `campaign_principal_changed`), never capacity/scoped-source diagnostics or counters. A matching same-key/same-intent receipt returns the original retained result plus freshly read current state/capabilities **before** new audience, capacity, expected-version, expiry or context admission checks and without settlement/new effects; a different intent returns the existing operation conflict. Current native and actor authority still govern every replay.
4. Only with no retained matching receipt, refresh canonical bindings/profiles/history coverage, complete source set, grant/policy/consent and campaign state for a **new admission**. If refreshed membership needs an additional User, return a refresh conflict and restart a fresh transaction after the native/actor/receipt checks; never acquire a late User lock or silently retain a prefix. Then recompute and expose any empty/over-cap/capacity/expiry/source refusal. Provisional preflight diagnostics never substitute for these refreshed checks, and no campaign-derived refusal may preempt the receipt path. This deliberately gives up the early no-large-lock optimization rather than adding a second authentication route.
5. On a new submit admission, lock the **existing** owner `advertiser_profiles` row `FOR SHARE`, refresh after waiting and freeze chosen brand/source. An absent-row fallback is frozen from canonical history-protected data (or localized unnamed sender); a later insertion cannot replace it. Lock actually used social/account rows in stable table/key order, then lifecycle/job and quota projection keys in scope/window/key order. Approval never resolves current sender/templates/base again; it loads the immutable submission envelope.
6. Obtain authoritative UTC time after waits, then re-evaluate review/dispatch expiry, current limits/window, metric freshness (if any separately admitted proof exists), cooldown, exact expected versions and context. Append all relevant facts/projections/receipt or roll back all. No wallet/item locks or network work.
