Bounded lock and query design
----------------------------
scripts/residual_purge_sql.py only compiles SQL strings. It never opens a
production connection. Its inputs are the pinned approved scope and an
authenticated selective snapshot, not an arbitrary account/order selector.

Target rows are read, checked, row-locked and deleted through complete primary
keys. The scripts never hash all orders to find the two target records.
The chosen PostgreSQL system identifier, database, schema, Alembic head,
columns, constraints, trigger set and trigger function definitions are pinned.
All original trigger states are restored and checked before COMMIT.

Immutable fact tables require brief table-level write exclusion to alter
their guards. Logical UUID anchors without an FK are also fenced. The plan
derives an explicit subset of tables rather than locking the whole schema.
The live metadata currently yields 65 table write fences. users/orders use
SHARE UPDATE EXCLUSIVE, compatible with ordinary ROW EXCLUSIVE DML, plus
FOR UPDATE NOWAIT on the exact target rows. No full users/orders write pause.
Tests prove unrelated user/order inserts and updates proceed while the target
rows and immutable guards are locked. Registration/profile, financial and
queue writes to fenced tables can wait briefly; zero delay is not promised.

Every acquisition is NOWAIT, including the existing shared financial/history
barrier (pg_try_advisory_xact_lock). Busy root rows, active history readers,
writers, schema maintenance or fact writers abort the attempt immediately.
No retry loop, worker shutdown, queue drain or service restart is performed.
The transaction checks a three-second budget before mutation, after each
table and before COMMIT. Statement timeout is 750ms; idle transaction timeout
is two seconds. Commit/WAL flush itself can add time after the final budget
check. Hold the existing /tmp/ugc-production-deploy.lock in the eventual
operator wrapper so deployments/migrations cannot overlap the cleanup.

Incoming FKs include CASCADE/SET NULL. Logical UUID/text/JSON references in
fenced tables, identity facts and current confirmations are rechecked after
the backup, before mutation. Root-key changes, new outside facts/proofs,
columns, constraints, triggers or a different cluster abort without a partial
result. Foreign keys/CHECK constraints stay enabled. No TRUNCATE, DISABLE
TRIGGER ALL or session_replication_role bypass exists.

Session-local statement/error payload logging is suppressed before any raw
restore document is sent; psql output is terse and does not echo input.
Insufficient logging-control privileges or independent pgaudit statement
capture prohibit execution rather than exposing backup contents. These
settings affect only the transaction and revert on commit/rollback.

Preparation checks structured ownership of instagram_stats by user_id/FK.
The unchanged external provider raw_response is an opaque cache payload and
is not scanned for internal UUID substrings. This matches its producer and
avoids an expensive full provider-archive scan. Other structured/declared
business references remain checked. The blob is neither exported nor deleted.
